# Agent capability implementation and iterative replays

These user-authorized evaluation captures preserve implementation learning for cloud-only continuation. Original test sources and questions are unchanged; no re-ingestion, embedding/index policy, image cap, model deployment or context-budget increase was used. All four replay snapshot checks report unchanged source generations, revisions and artifact hashes. The same 48,000-token budget was used. A replay starts fresh, then carries the first two casual turns and the three-turn meeting sequence in the same conversation, matching the original casual order.

[Live capability probes](live-capability-probes.json) independently exercised document-scoped vector search, evidence-handle source expansion, a full lightweight outline, and selected Office image reads. Every direct inspection read stored assets; there were no new layout, vision-description, embedding or index-write operations for the inspections. Source-region expansion performs a bounded source-location query and Blob reads, not a whole-report model-context load. The current paragraph-extent refusal was additionally checked locally after the replay; these model captures do not test that later precision guard.

[Metrics-only summary](../../../../records/agent-capabilities-20261027.json) separates RU, provider input/output tokens, model/tool calls, repair calls, retrieval time, total time and provider wait. Input tokens are cumulative across calls, not peak context. Query embedding tokens are not summarized in this record; they are not assumed zero. Native image accounting is model input, not new vision-description work.

The stages are iterative changes, **not four controlled replicas** and not a general before/after performance benchmark. v4's three-turn meeting sequence used 57.72 RU and 122,563 model input tokens; the original observed sequence used 349.53 RU and 133,023 input tokens, but one path per condition, changed tool behavior, output sizes, quota waits and model variability prevent causal speed/cost conclusions. Use repeated held-out evaluations for an accepted performance claim. The first casual diagram sometimes became more expensive in the new path, showing why per-case evidence matters.

## Answer-quality assessment and remaining work

- The diagram is now answered directly with a qualitative size comparison and a displayed figure; conditional referents improve in some runs. Inferred captions and internal figure locators still sometimes appear too confidently in model prose.
- The map is displayed in later runs, with correct W markers and waiting-list plots. The possible “Plot 4” reading of “plot for” is **still not reliably addressed**. Some prose speculates about which plots an outside marker serves, without source support. A new source capability cannot guarantee an interpretation the model fails to consider.
- The meeting question receives multiple useful report images in its initial answer. Later runs retrieve numerical findings (18.5% task success / 17.6% satisfaction on page 44, and in v3 22% information-sharing on page 41), with source text and some qualifications. These interventions do **not isolate the quantity of context**, and the opening synthesis can still overstate causality or persistent-memory evidence. Sample/comparator completeness, reuse-rights claims and figure relevance still need reviewer scrutiny.
- v3's unrelated-topic follow-up contamination was an adapter-reminder defect; v4 corrects that reminder and its final answer stays with the report. These small replays do not establish universal follow-up correctness.
- Display attachment availability is independent of supplying pixels. A native input withheld for budget can still be displayed; no re-ingestion, crop regeneration or automatic all-images gallery is required.

This is mechanism validation and focused integration evidence, **not blanket answer-quality signoff**. The remaining evaluation gates are held-out paraphrases, deliberate ambiguity, misleading premises, near-match figures, multi-file variants, negative evidence and repeated runs. Do not hard-code these source pages, facts or question strings into production routing. Exact source PDFs/Office files and the original test captures remain in the parent pack for independent review.

All runtime identifiers/tool library names are replaced by role labels, and signed links/environment details are removed. Sanitized historical handles are comparison artifacts, not usable current API selectors.
