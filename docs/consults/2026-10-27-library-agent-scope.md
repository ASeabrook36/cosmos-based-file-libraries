# Boundary between library tools and consuming-agent behavior

The user clarified that an apparent numbered-reference ambiguity was a typo, and asked us to avoid making its handling a large development task. They also questioned whether judging a piece's subject matter before sharing was creeping into agent development. This narrows the follow-up after E49.

The file library returns relevant candidates, exact stored source material, selected images, provenance, scope/omissions and validated references within the platform's authorization boundary. It does not decide whether a subject is appropriate to share, author a user's argument, or supply a general language-understanding/claim-verification system. The consuming agent selects evidence and figures that answer the request, judges relevance and claim strength, and clarifies material ambiguity. The demo exercises that integration; it does not establish universal reasoning accuracy.

An uncommitted experiment added separate interpretation and semantic-review model passes, structured claim assessments and special numeric-homophone candidates. That was removed following this clarification. It introduced extra model calls, schema/quotation failures and degraded fallback answers; any isolated successes do not justify expanding this project's scope. The [sanitized experimental evidence](../../records/agent-scope-experiment-20261027.json) is retained so a future cloud agent can understand the rejected direction. It is not an accepted benchmark or shipped functionality.

Only a small reference-adapter instruction correction remains: lead with the actual study intervention and comparison; distinguish direct evidence for the user's hypothesis from related evidence; do not equate training/alignment/facilitation changes with an isolated increase in context or persistent memory. Unknown samples/comparators stay unknown. This instruction is guidance, not a guarantee of scientific interpretation.

No new model-based sharing gate, extra interpretation/review calls, typo-specific code, API/ingestion/storage/index changes, or new library requirements are introduced by this follow-up. E49's existing scoped retrieval, bounded reads, direct image inspection, progress hints and mechanical presentation checks remain. Remaining agent reasoning errors should be recorded as consuming-agent limitations rather than automatically expanding the library backend.
