## Verification boundaries

Focused regressions cover projected search/read/page-image results with native inputs intact, absence of signed links/geometry in tool text, exact preservation of full-read section text, token savings, provider-usage fallback and new-image reservations, source ordering, generation visibility, personal binding, parent sizes, and bounded concurrent loading/cancellation without crop uploads. Existing checkpoint, overlap, metadata, lifecycle, completeness and budget tests continue to apply.

Live validation uses a separate four-format invented corpus, with later text added to the PDF, Word file and deck to make interleaving observable. Only metrics and booleans enter [the record](../../records/retrieval-followups-20261027.json); original unredacted captures, signed links and runtime IDs stay outside the repository. Sanitized observed answers and replay material were subsequently published in the user-requested [portable evidence pack](../testing/2026-10-27/README.md). Real-model smoke checks establish composition/presentation, not broad recall or a controlled latency improvement.

Existing documents remain readable. Reprocess chosen documents normally to obtain new enriched reading order and DOCX text locations. No bulk reprocessing is triggered. Refresh consuming adapters when deploying the API/worker; compact text does not revoke already issued image capabilities or remove the cross-client visibility caveat in N13. The configured per-document crop bound can multiply across worker lanes; aggregate memory and cross-process quota remain capacity work.

All **600 tests passed**, with lint, formatting, diff and private reference-privacy checks clean. The live projection reduced full-read text tokens by **30.6–33.4%** on these four small fixtures. Both real-model questions returned valid inline image references; the vague-figure question needed one search, while the mixed question completed a full read and supporting passage retrieval. It also requested an unnecessary same-page image read alongside the complete read. The adapter deduplicated native inputs, but model tool-selection efficiency remains evaluation work. These observations are recorded without claiming a general speedup or routing guarantee.

## Subsequent natural-language test (E46)

The later uncoached, multi-turn test exposed a real integration gap: eleven document-grouped searches returned one passage each while the model needed multiple passages within a known report. The loop exhausted its round bound, and a full read could not fit the configured context budget. Stored later-page evidence and images were verified independently; ungrouping increased the result count but focused topic formulation was also necessary. Two further user requests were needed before the model displayed several useful image candidates it had retrieved. Mode signalling/recovery and proactive evidence/image selection remain unfinished integration work. See [E46](../evidence.md#e46-natural-multi-turn-testing-exposed-a-document-grouping-trap-and-evidence-selection-gaps-2026-10-27--observed-live-read-only-diagnostics) and the [metrics-only record](../../records/casual-retrieval-friction-20261027.json). No operational code or configuration changed during that review.
